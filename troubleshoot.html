When a mod does not draw right

What to check, by symptom, when a mod does not show, looks wrong, ignores its key or the game crashes.

Find your symptom below and work down its list; most problems end at the first or second check.

#Where to look

Where What it tells you
The overlay's Wardrobe (Home in game) Every mod Overtone loaded, by character, on or off. A green dot means it is on screen.
The overlay's Tools → Report Whether mods are drawing at all, from a few seconds after the game starts.
Timbre's In game panel What is on screen, and each enabled mod that is Not on screen or Drawn as the game's.
Timbre's Settings → Runtime → Diagnostics How the last run went: Nothing was wrong, It complained or Something failed.
The log %LOCALAPPDATA%\Overtone\wuwa\overtone.log; paste the path into Explorer. Each game start adds a run beginning === run started. Search it for the mod's name: no mention means Overtone never loaded it.

Is it the mod or Overtone? If you have the XXMI Launcher, install the mod's archive into XXMI's own Mods folder (not your Overtone library) and look at it there. A mod that looks wrong in XXMI too is broken: tell its author.

#The overlay does not open

Home opens nothing, so Overtone is not running.

  1. The game must run on DirectX 12. If the log's last run says the game was started on DirectX 11, set the game's launcher, or the XXMI Launcher, to DirectX 12.
  2. In Timbre, Settings → Runtime → Setup must say Installed and current. If not, press Play once.

#The mod does not show at all

  1. Mods on? F8 turns every mod off and on; so does the Mods on chip at the top of the overlay.
  2. Ray tracing off? With ray tracing on, reflections, ray-traced shadows and far-away characters show the game's outfit. If no mod draws at all, Tools → Report says Ray tracing is on: turn it off in the game's graphics settings and restart the game.
  3. Is the mod in the Wardrobe?
    • No described mods in the library.: start the game from Timbre's Play once, so Overtone finds your library.
    • Listed but off: turn it on with its switch, there or in Timbre.
    • Not listed: Timbre has not converted it yet. Open Health and press Describe under New mods; the game shows it a moment later, or at F10.
    • Not listed, and it sits in a folder another mod manager made (IMM_TEMP_ and a number, IMM_INI_BACKUP, or a restore point named RESTORE- and a date): those folders are ignored. Add the mod again in Timbre from its download. Health offers to send what is in those folders to the Recycle Bin.
  4. Is it on screen? Listed, but never with a green dot:
    • A mod for a skin draws only while the character wears that skin.
    • Of two mods for the same outfit, only one draws. The log names both: <mod> claims the same components as <other> -- the first is drawn. Turn one off.
    • Tools → Report says No mod matched: after a game update, see the next section.
  5. Still nothing? Search the log for the mod's name. A line ending in not drawn says why.

#It worked before a game update

An update can change the character's model so a mod no longer fits it, and the mod draws nothing. Overtone cannot repair this yet. The log may say on screen and never drawn: <mod>.

Install the author's updated version through Timbre (Add your mods).

#Part of the mod shows as the game's own

  • The mod is missing a file. The log says <mod>: mesh <name> claims nothing, and the game draws its own: <file> cannot be read. Install the mod again through Timbre.
  • The log says N refused at format X, and this runtime reads Y: Timbre and Overtone are different versions. Start Timbre, which converts such mods again, and press Play to update Overtone.

#Wrong or missing textures

  1. Settings → Drawing → Replace textures must be on (the default).
  2. Textures that start blurred and sharpen are still loading.
  3. Some textures get their role, the job they do (colour, bumps), only the first time the mod is played. If one is still wrong, open the mod in Timbre (In game → Model), click a part's colour swatch, and give each texture under Swapped here, no role yet a role. Use N suggestions takes Timbre's guesses.
  4. A tattoo or lace part shows as a solid panel: Settings → Drawing → Cut parts by their masks must be on (the default).
  5. Not drawn yet: glow maps, so glowing parts look plain, and some hair light maps and highlights, which keep the game's.

#A change to a description does not show

  1. Settings → Loading → Reload on file change must be on (the default); otherwise press F10 after each save.
  2. A piece with a material, or a choice that wears the part while it is chosen, covers what [component.<n>] says (Create a mod).
  3. Search the log for the mod's name. line <n>: ...; it is passed over names a line Overtone ignored, such as a misspelt role or a part that names no mesh; would not read: says why the whole file was refused.

#Parts flicker, stretch or vanish

Check the mod in XXMI first (see Where to look). Each fix below is a setting under Settings → Drawing, on by default.

You see Check
A clone, twin or co-op copy takes another's pose Pose each copy separately is on
The face does not move Face morphs on the GPU is on
The mod turns into the game's model from far away Draw mods at distance is on
A see-through part, such as sheer cloth, is missing Build see-through pipelines and Draw see-through parts are on; restart the game after changing the first
The character fades out when the camera is close That is the game. F7 stops it, but may show what the game hides on purpose.
A few vertices stretch for one frame Send the log (below)

#A key does nothing

  1. A mod's keys work only while it is on screen, with a green dot in the Wardrobe.
  2. While the overlay is open, keys it uses itself go to the overlay: arrows, Enter, Space, Esc, Tab, PgUp, PgDn, Q, E and /.
  3. Two mods on screen with the same key: mods one character wears, such as an outfit, a face and her weapon, all take the press, as in WWMI. Between two characters on screen at once, such as in the character menu, it goes to the one drawn most, and does nothing where they are drawn alike.
  4. Use the Wardrobe instead: its arrows step a switch and Wear puts on a look, without any key.
  5. To change a mod's key, open the mod in Timbre and click the key in its Variants list. The game uses this marks a key the game already needs.
  6. Still nothing: report it. The log says what each press moved, or why it moved nothing.

#The game crashes or hangs

  1. Before starting the game again, report it. The report file holds the log, any crash report, your settings and profile.
  2. Press F8 to turn mods off. If the crash stops, turn the newest mods back on one at a time to find the one.
  3. If it crashes at start, under Settings → Runtime → Setup try Start the client directly, and switch off ReShade or any other tool listed there.

#Reporting a problem

  1. In Timbre, press Report at the foot of the left bar. Timbre also offers it in a banner when the game closes after a problem.
  2. Pick what went wrong and say what happened.
  3. Search for the mod if one is involved.
  4. If the game hung and Timbre offers it, tick Include the hang dump. It may hold your Windows user name.
  5. Press Continue. Your report file is saved and shown in its folder, and GitHub opens with your note filled in. You need a free GitHub account.
  6. Drag the file onto the box on GitHub, then press Submit new issue.

Before you press Continue, What's sent lists what the file holds. Your Windows user folder is hidden in it.

Without Timbre, attach overtone.log, and overtone-native-crash.txt if there is one, from %LOCALAPPDATA%\Overtone\wuwa. Copy them before starting the game again.

#For mod authors

  • Tools → Report → Mods on screen has a row per mod. waiting above 0 means its files are still loading. refused or no palette above 0 with drawn at 0 means Overtone found the mod and gave its draws back to the game: send the log.
  • The sheets column counts the mod's textures placed. At 0 with Replace textures on, the description gives those parts no role.
  • The log's line per mod, sheets N placed (N no-role: N abstained, N wrong-kind; N no-view), says why textures were left out. Tools → Debug → Survey game textures logs what the game bound at each slot.
  • Tools → Report's counter toggles → ambiguous counts key presses two characters' mods tied over. The log's <key> pressed: line names the mods a press went to and what each moved, or why it moved nothing: a tie, no mod binding it drawn, its keys waiting for parts not drawn, or its conditions.
  • The log's N mods drawn from <folder> line says how many mods were read, and from where.

Applies to Timbre 26.1017.0 and Overtone 26.1017.0.
